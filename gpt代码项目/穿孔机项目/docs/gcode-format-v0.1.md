# 数控电火花穿孔机 G 代码格式草案 v0.1

状态：待控制器型号和现有程序样例确认。此文档先约定**上位机作业文件**的语义；设备驱动负责把作业指令转换成实际控制器协议。

## 1. 设计目标

- 用文本文件明确表达孔位、孔序、加工深度及工艺配方，便于查看、生成、校验和追溯。
- 常规定位使用熟悉的 G 代码；放电穿孔用上位机解释的扩展指令表示，避免把伺服间隙控制伪装成普通恒速钻孔。
- 程序在执行前完成静态校验。加工期间的放电脉冲、间隙反馈、Z 轴进退、短路处理和硬件联锁由实时控制层负责。

## 2. 文件与基本约定

| 项目 | 约定 |
| --- | --- |
| 扩展名 | `.ngc`；UTF-8 文本，LF 或 CRLF 换行 |
| 单位 | 首段必须为 `G21`（毫米） |
| 坐标方式 | 首段必须为 `G90`（绝对坐标） |
| 工作坐标系 | 首段必须明确选择 `G54`；其原点及 Z0 定义须在作业设置中确认 |
| XY 坐标 | 工作坐标，单位 mm；孔位必须同时给出 X、Y |
| Z 坐标 | v0.1 的 G 代码不直接移动 Z；加工前由操作界面发起 Z 快移/点动，加工中由 STM32F407 闭环控制；穿孔循环使用正数深度 `D` |
| 注释 | 圆括号注释 `(文字)`；不在一对括号内嵌套括号 |
| 行号 | `N` 行号可选；不参与执行语义 |
| 小数 | 句点作小数点，不使用千位分隔符 |
| 一行一指令 | 一行只放一个 G/M 指令及其参数；空行和纯注释行允许 |

程序必须以 `%` 开始和结束，以 `M2` 结束执行。解析器拒绝未列入白名单的指令，而非忽略未知代码。

找中页可根据铜管外圆碰边结果改写当前 G54 工作零点；程序内的 `G0 X… Y…` 随后按新的 G54 解释。铜管半径只参与找中偏置计算，不会自动改写每个孔位，也不实现 G41/G42 加工路径刀补。重新装夹或改变 G54 后须复核孔位与 Z0。

## 3. v0.1 指令白名单

| 指令 | 含义 | 参数与限制 |
| --- | --- | --- |
| `G21` | 毫米制 | 必须在第一条运动指令前出现 |
| `G90` | 绝对坐标 | 必须在第一条运动指令前出现 |
| `G54` | 选择已标定的工作坐标系 | 必须在第一条运动指令前出现 |
| `G0 X… Y…` | 快速移动到孔位 | X、Y 同时提供；由控制层实施软限位校验 |
| `M200 P… D…` | 在当前 XY 位置执行一次电火花穿孔循环 | `P` 为正整数配方 ID；`D` 为正数、单位 mm，表示从已确认工件表面向下的最大允许加工深度 |
| `M0` | 操作员暂停 | 恢复前重新检查设备状态 |
| `M2` | 结束程序 | 必须是最后一条可执行指令 |

`M200` 是**本系统上位机扩展**，不能直接发送给未经适配的 LinuxCNC、GRBL、grblHAL 或厂家控制器。适配器将其拆解为设备支持的工艺动作。`D` 是安全上限，不等于保证达到的实际孔深；是否穿透由工艺配方与反馈判定。

## 4. 示例

```gcode
%
(JOB: plate_A_001)
(WORK: G54, surface Z0 calibrated before run)
G21
G90
G54
G0 X10.000 Y20.000
M200 P1 D5.000
G0 X30.000 Y20.000
M200 P1 D5.000
M0
G0 X30.000 Y40.000
M200 P2 D3.000
M2
%
```

执行含义：使用 G54 定位到三个孔位；前两个孔使用配方 1，加工深度上限 5 mm；人工暂停后，第三个孔使用配方 2，加工深度上限 3 mm。

## 5. 配方与作业快照

配方 `P` 不写成控制器特有的 G 代码参数。上位机保存配方表，至少包括电极规格、脉冲参数、冲液方式、间隙控制阈值、短路回退策略、单孔最长加工时间和穿透判定方式。创建作业时连同配方**版本快照**保存；运行前检查每个 `P` 都能解析到快照。这样同一份作业不会因为日后修改配方而改变实际工艺。

## 6. 执行前必须校验

1. 文件结构、编码、参数类型、重复或缺少的模式声明、未知指令。
2. 每个 XY 孔位是否落在已标定工作范围内；每个 `D` 是否小于设备及工装限制。
3. `G54`、工件表面 Z0、配方版本和电极规格是否与本次装夹匹配。
4. 急停、门禁、液位、冲液、脉冲电源、轴限位等必要联锁是否就绪。
5. 在仿真/预检界面列出孔位、顺序、预计动作和全部告警，确认后才允许运行。

联锁和急停必须由控制器/硬件闭环实现；PyQt 界面失联时设备应进入安全状态。

## 7. 待确认的设备信息

- 控制器品牌、型号、固件及其实际支持的 G/M 代码和通信协议。
- 轴配置：XY、Z，是否有电极旋转轴、自动换电极、冲液/水泵。
- 工件表面 Z0 的标定方法，孔深定义，以及穿透检测信号。
- 是否已有厂家 `.nc`/`.tap` 样例；如有，优先编写导入适配器或调整本草案。

## 9. Z 轴控制权与模式切换

**原则：Z 轴的脉冲/方向信号或伺服运动命令始终由下位机产生。** PC 只发送目标位置、速度和模式请求，不直接产生实时步进脉冲。这样可避免操作系统调度和通信延迟影响加工中的间隙控制。

| 模式 | PC 能发的命令 | STM32F407 职责 |
| --- | --- | --- |
| `IDLE` 空闲 | 回零、请求进入手动模式 | 保持 Z 停止，监测限位及联锁 |
| `MANUAL_Z` 加工前定位 | Z 快移到指定位置、低速点动、停止、设置/确认工件表面 Z0；已接线时可受控手动测试辅助输出 | 执行限速、加减速、软硬限位和位置反馈；手动放电须另受冲液、Z0 和硬件联锁约束，自动作业启动前关闭手动输出 |
| `ARMED` 待加工 | 提交本孔配方、深度上限并请求开始 | 停稳 Z，锁定坐标与参数，检查联锁及反馈有效性 |
| `EDM_Z` 穿孔中 | 暂停、停止、急停请求；只读状态 | 独占 Z 控制，根据放电间隙反馈进给、回退及短路处理；拒绝 PC 的快移/点动命令 |
| `RETRACT` 退刀 | 停止请求；只读状态 | 先关断放电，再按安全条件退至安全位置 |
| `FAULT` 故障 | 故障查询和受控复位 | 关断放电并阻止自动恢复，按故障类型停止或安全退刀 |

建议切换序列：`MANUAL_Z` 定位与表面 Z0 确认 → PC 发送配方与 `D` → STM32F407 检查 Z 已停稳、坐标有效、行程余量、间隙传感器及联锁 → 下位机回报 `ARMED` → PC 发 `START_HOLE` → 下位机进入 `EDM_Z`。单孔完成后，先关断放电并退刀，再报告完成；PC 只有收到 `MANUAL_Z` 状态后才可再次发快移/点动。

控制权切换必须由下位机状态机确认，不能只靠 PyQt 按钮变色。每条命令带序号，通信协议返回“已接收”和最终执行结果；超时后 PC 查询实际状态，不盲目重发移动命令。暂停、正常停止、故障和急停应有不同状态与处理路径。通信中断时，下位机应独立关断放电并停止进给；是否允许自动退刀取决于电源、限位和联锁状态，不能假定总能安全退刀。硬件急停直接切断危险输出，不能依赖 PC 或普通通信命令。

`M200` 触发一次自动穿孔循环，内部才会切换到 `EDM_Z`。加工前的 Z 快移/点动属于设备准备操作，**不写进 v0.1 的孔位 G 代码**；若以后确需程序化 Z 快移，再单独定义可验证的安全语义。

Z 轴位置反馈模式（编码器、光栅尺、双闭环）在[位置反馈设置草案](feedback-settings-v0.1.md)中定义；它是设备设置，不由 G 代码逐孔切换。
